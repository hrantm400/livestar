# Stellar — Live Celebrity Activity Index

A live, interactive map of public celebrity activity. Aggregates announced
events, news mentions, social signals and editorial profiles for **412
indexed celebrities** across 8 free public APIs — no API keys, no scraping,
no real-time location tracking.

> **Note.** This is a portfolio / demo project. It surfaces only public
> data (Wikipedia, Wikidata, GDELT news, public schedules) and is **not**
> a person-tracker. No predictive location, no user-submitted sightings.

---

## Features

- **412 celebrities** across music, film, sports, business, fashion — globally
  diverse: Bollywood, K-pop, Chinese cinema, Russian artists & athletes,
  Latin music, African afrobeats, Japanese anime, plus the usual Western
  pantheon. All resolved via Wikipedia REST → real Wikidata QIDs.
- **Live, interactive map** (MapLibre GL + CartoDB dark tiles) with native
  WebGL pin rendering — smooth at any zoom, no DOM marker drift.
- **3 view modes** — Pins · Heatmap · Globe (3D projection).
- **Editorial detail panel** for each celebrity: Wikipedia bio + image,
  Wikidata-derived social handles & birthplace, GDELT news articles,
  iTunes recent releases, TheSportsDB schedules, Reddit trending score,
  30-day Wikipedia pageviews sparkline.
- **Cmd+K command palette** with federated search — local registry first,
  falls back to Wikipedia REST for any human in the encyclopedia.
- **Follow** (localStorage with cross-tab sync), **Share** (URL with
  `?focus=` deep-link), **Refresh** (busts the in-memory feed cache),
  filter by category and time window (Past / Now / Upcoming).
- **Hover prefetch** — sidebar / map pins warm the profile cache before
  the click, so the detail panel opens instantly.

## Live data sources

| Source | What we pull | Auth |
|---|---|---|
| Wikipedia REST | Bio, image, canonical title, Wikidata QID | none |
| Wikidata SPARQL | Twitter / Instagram / TikTok / website / birthplace | none |
| Wikipedia Pageviews | 30-day daily view counts (real popularity proxy) | none |
| GDELT 2.0 | Recent news mentions + 7-day mention volume timeline | none |
| Reddit JSON | Trending mentions in the last 24h | none |
| iTunes Search | Latest releases for music artists | none |
| TheSportsDB | Next / last events for athletes | test key `3` |
| Nominatim / OSM | Geocode venue strings → lat/lng | none |

All sources go through a hardened JSON fetcher with timeouts, retries, a
real User-Agent, and a TTL+SWR in-memory cache.

## Architecture

```
app/
  layout.tsx              fonts (Fraunces variable, Inter, JetBrains Mono)
  page.tsx                3-pane shell (sidebar / map / detail) + filter bar
  globals.css             design tokens, glass surfaces, refined map popups
  api/
    celebrities/          GET — light list of all 412 (sidebar)
    celebrity/[id]/       GET — full profile (fan-out to all sources)
    feed/                 GET — global live feed (sport events + cached profile events)
    search/               GET — federated search (registry + Wikipedia)
    health/               GET — diagnostic
components/
  Header / Sidebar / MapView / DetailPanel / FilterBar
  CommandPalette          Cmd+K with external Wikipedia results
  Toast / KeyboardLayer / DeepLinkBoot
lib/
  registry.ts             reads data/celebrities.json + curated overlays
  aggregator.ts           buildProfile / buildList / buildFeed — fans out + merges
  cache.ts                TTL + stale-while-revalidate cache with peek()
  follows.ts              localStorage-backed Set with cross-tab storage event
  share.ts                clipboard + URL focus param helpers
  use-data.ts             client hooks: useCelebrities, useProfile, useFeed, prefetchProfile
  store.ts                zustand UI store
  sources/
    _fetch.ts             hardened JSON fetcher (timeout / retry / UA / rate-limit)
    wikipedia.ts          summary endpoint
    wikipedia-search.ts   full-text search
    wikidata.ts           SPARQL queries (split for timeout safety)
    gdelt.ts              ArtList + TimelineVol (5.5s rate-limited)
    pageviews.ts          per-article 30-day view counts
    reddit.ts             public JSON search
    itunes.ts             artist + release lookup
    sportsdb.ts           player + next/last events (with ASCII fallback for diacritics)
    nominatim.ts          1.1s rate-limited geocoder
data/
  celebrities.json        412 entries with QID + Wikipedia title, generated by
                          scripts/seed-from-wikipedia.mjs
scripts/
  seed-from-wikipedia.mjs hand-curated name list → resolves through Wikipedia REST
  build-registry.mjs      alternative SPARQL-based importer (flaky upstream)
```

## Run locally

```bash
npm install
npm run dev          # http://localhost:3000
```

To re-build the celebrity registry (~2 min, hits Wikipedia REST):

```bash
node scripts/seed-from-wikipedia.mjs
```

## Performance notes

- Map renders all event pins via a single GeoJSON source + 4 native WebGL
  layers (pulse / halo / pin / label). Zero per-marker DOM, smooth pan
  even with hundreds of events.
- Profile shell paints instantly from the registry brief while the full
  fan-out (Wikipedia + Wikidata + GDELT + Reddit + iTunes + Pageviews +
  TheSportsDB) resolves in the background. Hover on a star → that fetch
  is already in flight by the time you click.
- All upstream calls are TTL-cached process-wide with stale-while-revalidate
  windows tuned per source (geocoding 30 days, GDELT 10 min, Reddit 3 min,
  pageviews 6 hours, etc.).
